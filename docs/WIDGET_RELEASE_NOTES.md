# 借拍 0.3.2：照片加载减量与分阶段排查（待真机验证）

机主确认 0.3.1 在 iOS 18.7.8 的所有尺寸仍停在系统灰色骨架占位，少量照片也会发生，没有开启 iCloud 优化。上一版普通应用里的 PhotoKit 检查通过，没有证明系统托管小组件的归档、渲染和进程内存正常。

本版依据官方图片内存资料与开发者亲历案例，减少图片工作量并加入组件内排查，仍为候选版。尚未取得机主设备的 Jetsam/崩溃报告，不能把内存超限认定为已确认的唯一原因。[完整调查与来源](https://github.com/kevin3627713/session-camera/blob/experiment/transparent-widgets-ios18/docs/WIDGET_PHOTO_INVESTIGATION.md)。

- 时间线和快照每次只准备当前一张照片，不再提前请求六张。保留 highQualityFormat、忽略低清回调、三倍点数和最长边 1200 像素。
- PhotoKit 请求加入中心裁剪，最终渲染器使用标准动态范围。缓存尺寸检查读取 ImageIO 元数据，减少不必要的 UIImage 创建。
- 在随机照片样式的原生编辑面板增加“照片排查”，默认关闭，可以分别测试绘制、来源读取和图片请求。仍是五种样式，不新增另一种小组件。
- 系统日志加入各处理阶段、实际回调尺寸/位深及进程内存采样，不记录照片内容、资产 ID 或相册名，不上传数据。

更新后先保持“照片排查”为关闭。如果仍不显示，在现有组件里依次选“1 · 测试图与文字”（应显示红蓝色块）、“2 · 只读取相册”（应显示可用照片数量）、“3 · 请求照片但只显示结果”（应显示像素尺寸等文字）。第一步不需要来源或编号，后两步保留已经选好的来源和编号。记录停在哪一步，再把排查关闭恢复正常照片。无需先删除组件。

每次只准备当前照片的取舍：需要系统在下一周期边界重新请求，可能受 WidgetKit 更新预算影响而延后，短周期尤为明显。没有承诺严格按分钟切换。

仍在 `experiment/transparent-widgets-ios18`，主程序 / 扩展版本均为 0.3.2、build 7，仍恰好一个扩展，沿用同一主应用和扩展 ID。保留原有五种样式、原生编辑、默认点击不打开应用、每个实例独立编号及来源。用原签名身份和包名映射覆盖更新，保留 SessionWidgets.appex，沿用现有应用槽位。
