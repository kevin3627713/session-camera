# 照片跳转诊断 0.1.3 · 独立 App

机主在未越狱 iOS 18.7.8 上确认：外部动态快捷指令能在目标相册打开照片，但有约 0.5 秒完整快捷指令页面；从系统快捷指令小组件运行固定 C 链接则直接进入照片，或只显示进度提示。

新增“8 · 主应用：快捷指令执行器”和“9 · 中转扩展：快捷指令执行器”。使用系统小组件的同一父类 WFWorkflowRunnerClient、数据库名称描述符和 widget 运行请求，直接提交完整照片 URL 文本，不通过 shortcuts:// 启动完整 App。保留真实自签调用身份，记录接口可用性、执行请求模式、当前进程访问能力、委托 NSError 与耗时。系统权限检查是否接受第三方仍需真机结果，不能由系统小组件的成功替代。

## 操作步骤

1. 使用原来的签名身份，覆盖安装 0.1.3 / build 4，并保留 PhotosNavigationShare.appex。无需卸载诊断 App，原相册、照片及配置会保留。
2. 检查系统快捷指令“借拍相册跳转”的动态版本：第一个“URL”动作只放蓝色的“快捷指令输入”变量，第二个“打开 URL”使用第一个动作输出。如果名称不同，稍后在诊断 App 中填入实际名称。系统小组件对照使用的固定链接副本可以保留，本轮需要动态版本。
3. 打开诊断 App，点“清空测试记录”；保留或选择一个相册和其中一张照片，关闭“使用自定义 URL”，预设选择 C。
4. 选择“8 · 主应用：快捷指令执行器”，核对“快捷指令名称”与第 2 步相同，点“执行跳转测试”。若无反应，最多等待约 15 秒让结果保存；若打开照片，核对是否仍在目标相册，以及是否完整显示过快捷指令 App。返回诊断 App 填写该记录的“实际页面”。
5. 对同一目标选择“9 · 中转扩展：快捷指令执行器”再执行一次，记录相同内容；中转收尾最多约 20 秒。方式 1–7 无需重测。
6. 点“复制完整诊断报告”提供这两条结果，并补充“有没有完整快捷指令界面”。报错、无反应或超时均保留真实结果，不需要卸载或重装。

保留清空记录、重置数据、11 个链接预设、解析检查与本机报告。此包是独立诊断 App，不包含借拍相机或照片小组件；借拍生产点击行为尚未更改。报告留在本机，按复制 / 分享按钮导出。

## 历史结果

0.1.2 / build 3 的 INCAppLaunchRequest / FrontBoard 方式 6 / 7 已由真机明确拒绝：底层 Security / Request is not trusted。0.1.3 保留旧代码用于研究，不再要求重复这两项。相关结果和新执行器的证据边界见[后台执行调查](../../docs/SHORTCUTS_BACKGROUND_EXECUTION.md)。
